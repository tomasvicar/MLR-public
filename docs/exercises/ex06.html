Exercise 6 — SVM, bagging and feature engineering

Build your own ensemble, then help an e-bike finish its trip

Builds on linear models and kernels, decision trees and ensembles and the preprocessing part of the second lecture. Task 2 is on paper.

1. SVM: C and kernels

On two species of leaves, build a standardization + SVM pipeline. Write a loop through several C values and collect training/validation accuracy and the number of support vectors. Use the plotting helper to see what changed.

Then compare a linear and an RBF kernel on circles. Try a much larger gamma. Explain the observed training/validation difference. A polynomial kernel is an optional extension; there is no separate primal/dual coding task.

2. A tree on paper

Draw these six points with two different symbols:

Point x₁ x₂ Class
1 1 1 A
2 2 3 A
3 3 2 B
4 4 4 B
5 5 1 A
6 6 3 B
  1. Try the cuts x₁ ≤ 1.5, x₁ ≤ 2.5 and x₂ ≤ 2.5.
  2. Assign each side its majority class; count correct predictions across all six points.
  3. Select the best of these candidates. Split its remaining impure region once more.
  4. Draw the decision tree and trace one point through it.

Accuracy is the number of correct predictions divided by six. If a leaf has a tie, either label gives the same accuracy. This is a simple teaching criterion: DecisionTreeClassifier normally selects splits by Gini or entropy/log loss, not by this accuracy rule. There is no tree-depth experiment.

3. Write your own bagging

Use two leaf classes and a fixed training/validation split.

  • Run the supplied code: a reference tree and one tree trained on a bootstrap sample.
  • Extend the one-tree example into a loop to train 11 trees, drawing a fresh sample with replacement each time and keeping features and labels paired.
  • Collect their predictions and implement majority voting for the two classes.
  • Compare individual trees and the ensemble on the same validation data.

You write the loop and voting. No custom estimator class or BaggingClassifier is needed. Explain why trees differ and whether voting helped in this run; an improvement is not guaranteed.

4. Will the e-bike finish the trip?

You operate a shared e-bike service. Predict whether a planned trip will run out of charge (runs_out = 1) using information available before departure. The data are a reproducible teaching simulation, not real customer records or a validated battery-physics model.

First inspect the table: missing measurements, categories and unusual readings. Distinguish a valid extreme from an impossible value. Replace charge percentages outside 0–100 and nonpositive distances with missing values, then build a small pipeline with numeric imputation and categorical encoding. Fit learned preprocessing inside validation.

Use RandomForestClassifier for the baseline. Compared with your bagging, a random forest also considers a random subset of features at each split. Scaling is unnecessary for this model.

Create useful features. Start with nominal available energy, then test one further idea against the baseline on the same validation folds:

Idea Interpretation
capacity_wh * charge_pct / 100 Nominal energy available at departure
Available energy / distance Energy budget per kilometre
Ascent / distance Route climbing intensity
Cold-weather indicator or deficit A possible nonlinear temperature effect
Riding mode combined with route conditions An interaction between category and measurement
Missing-measurement indicator Whether an unavailable reading carries information

State your hypothesis before running the comparison. Keep forest settings and validation folds unchanged. Handle missing/invalid inputs without dividing by zero. The notebook uses imputation inside each fold before deriving numeric features. Compare three conditions: original columns, original columns plus available energy, and those columns plus your chosen addition. Record the mean validation accuracy and fold spread, then interpret the differences; lack of improvement is also a valid result. The list is a menu, not six mandatory tasks.

5. Search parameters, then extend with an agent

↓ Download everything for the final task (ZIP)

Includes the student notebook, e-bike CSV, complete agent specification and a getting-started README. After extracting, replace the bundled blank notebook with your own Task 4 notebook before starting the agent.

5a — teacher demonstration. On the same e-bike data, first follow a short grid loop, then an Optuna study. Each candidate is a complete pipeline evaluated on training folds. The demonstration tunes leaf size and feature subsampling; it does not reintroduce the removed depth experiment.

5b — your extension. Start with your own Task 4 pipeline and the same data, split and validation folds. Have the agent use Optuna to tune and compare k-NN, SVM, logistic regression, random forest and gradient boosting. Include a small set of preprocessing/feature choices, scaling where it matters and conditional model parameters. Keep a stated equal trial budget per algorithm and fixed seeds.

Optional editor: if you want to use VS Code on Windows, install it from PowerShell or Windows Terminal:

winget install --id Microsoft.VisualStudioCode --exact --scope user --accept-package-agreements --accept-source-agreements

Review the generated work yourself: leakage, validation, search spaces, reproducibility and whether the results justify the conclusion. Start a short validation-only smoke run (--trials 2 --cv-only) in class; it must not evaluate the test subset. Finish the full experiment and review at home. The notebook gives the complete specification and checklist.
