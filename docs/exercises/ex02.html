Exercise 2 — k-NN as an object, metrics, splitting, standardization

Turning last week’s script into a model, and measuring it honestly

Week 2 · builds on the second lecture (Performance evaluation, metrics, preprocessing) · bring a laptop; the first part of Task 1 and the first part of Task 3 are done on paper

▶ Open the notebook in Google Colab

What you will learn

  • How the number of neighbours \(k\) changes a prediction, and why \(k = 1\) is a noisy vote — first at the blackboard, then in code.
  • How to write a model as a class with fit and predict, and check it against scikit-learn.
  • How to compute accuracy, sensitivity, specificity, precision, \(F_1\) and balanced accuracy by hand from a confusion matrix, and how to check accuracy, the sensitivity/specificity pair and the two regression errors MSE and MAE, written in NumPy, against sklearn.metrics.
  • Why a model is measured on data it has never seen, and how much a single hold-out split moves.
  • Why k-NN needs feature scaling — the z-score and min–max normalization — and how to recognise four classic ways of reporting a number that is too good to be true.

Before the lab

  • Re-read the second lecture, especially the confusion matrix and the metrics derived from it, the hold-out split, and the section on scaling and leakage. The notebook uses exactly the same notation.
  • Make sure you can still read your own code from exercise 1 — euk_dist and the nearest-neighbour loop are the starting point of Task 1, and the data, the names X and y and the plotting helper are the same.

Tasks

  1. From NN to k-NN — vote by hand on seven leaves (below), then write the prediction as a function and watch a single leaf change its class as \(k\) grows.
  2. OOP and the scikit-learn API — implement CustomKNeighborsClassifier with fit and predict, and compare its predictions with KNeighborsClassifier on the whole dataset.
  3. Metrics — compute six metrics on paper from a small confusion matrix, then write accuracy, the sensitivity/specificity pair and the two regression errors in NumPy and check them against sklearn.metrics.
  4. Hold-out split — split 70 / 30 with np.random.permutation and with train_test_split, and see how much the result depends on the split.
  5. Standardization — classify leaves from height and stalk thickness, two features on very different scales, without and with standardization.
  6. Homework — choosing \(k\) on a validation set — the train / validation / test split and the scaler are given; you write the loop over \(k\), the plot, one single look at the test set and a three-sentence answer.
  7. Red flags — four snippets that run fine and report a number that is too optimistic. Diagnose each of them, and repair the fourth.

By hand

Two parts of the lab are done with the laptop closed.

Task 1a — the k-NN vote. The six leaves of exercise 1 and a seventh, invented for this exercise: an unusually large cherry that strayed among the walnuts. The new leaf is last week’s, \(h = 15\) cm and \(w = 7\) cm. Fill in the squared distance \(d^2 = (h_i - 15)^2 + (w_i - 7)^2\) and the rank of each leaf (1 for the nearest), then say what 1-NN and what 3-NN predict — and which of the two you would trust.

Task 3a — the metrics. A classifier decides for each of 100 leaves whether it is a maple (the positive class); 20 of them really are maples. Its confusion matrix — rows are the actual class, columns the prediction, as in the lecture — is:

predicted maple predicted not maple
actual maple \(TP = 15\) \(FN = 5\)
actual not maple \(FP = 10\) \(TN = 70\)

Compute, as exact fractions and then as decimals:

  • accuracy \(= (TP + TN) / (TP + TN + FP + FN)\)
  • sensitivity (recall) \(= TP / (TP + FN)\)
  • specificity \(= TN / (TN + FP)\)
  • precision \(= TP / (TP + FP)\)
  • \(F_1 = 2 \cdot \dfrac{\text{precision} \cdot \text{recall}}{\text{precision} + \text{recall}} = 2\,TP / (2\,TP + FP + FN)\)
  • balanced accuracy \(=\) the mean of the per-class recalls \(= \frac{1}{2}\left(\dfrac{TP}{TP + FN} + \dfrac{TN}{TN + FP}\right)\) — also for the two constant classifiers “always maple” and “always not maple”

Then answer in one sentence: the accuracy looks good, so why would you not want to report only that number?

Data

  • leaves.csv — 518 leaves, columns Leaf height [cm], Leaf width [cm] and Tree type (maple, cherry, walnut). The same table as in exercise 1.
  • leaves_stalk.csv — the same 518 leaves in the same order, columns Leaf height [cm] (3.8 to 25.5), Stalk thickness [cm] (0.05 to 0.40) and Tree type. The two features differ in scale by a factor of about 50, which is the whole point of Task 5.
  • leaf_measurement_stalk.png — where the two features of Task 5 are measured: the height of the blade and the thickness of the stalk just below it, marked on one leaf so that the difference in scale is visible. The same leaf as the two measurement pictures of exercise 1.

Both tables are read straight from GitHub, so the notebook runs in Colab with no upload.
